# Current method coverage and public design boundaries

This is a coverage map of the maintained generic instructions, not a reconstruction
of private prompts, original upstream files, work portfolios or operating manuals.
The [public design ledger](resources/provenance.json) separates recorded attribution,
intentional adaptations, independently fictional cases and unavailable evidence.
No historical line count, source fingerprint or real finding is a current fact.

## Implementation assessment

[Code review](code.md) retains Intent -> Architecture -> Implementation -> Polish;
all checklist families; automation-gap exceptions; one complete supported remedy;
actual consumers and conditional cleanroom cleanup; urgency/type/timing distinctions;
and consolidated open/resolved/withdrawn/aliased/not-reassessed prior claims.
[The fictional worked review](code-worked.md) exercises identity, ambiguity, consumer
compatibility and source-grounded revised dispositions without private projects.

## Ten structural diagnostic mechanisms

Every mechanism is explicit in [structural audit](smells.md), not limited to the
three example findings in [the fictional worked audit](smells-worked.md).

| Mechanism | Evidence and preferred boundary |
|---|---|
| Multiple reasons to change / solution sprawl | Cohesive collaborators behind a purposeful facade. |
| Duplicate transition loops / combinatorial explosion | One loop with narrow policy, not more boolean modes. |
| Primitive event clumps / recorder bypass | Typed context and one index/serialization/persistence owner. |
| Distributed configuration / shotgun surgery | Shared field metadata; scalar parsing versus cross-field invariants. |
| Multi-stage budget packaging | Request context, allocator outcomes and payload presentation. |
| Mixed parsing/correction/mutation/final-attempt policy | Typed candidates, per-item results and explicit mismatch policy. |
| Factory/closure/validation/projection entanglement | Dedicated validation/projection and per-run context. |
| Raw tool dictionaries crossing acquisition/guards/presentation | Stable outcomes and separate transition/presentation boundaries. |
| Divergent row adapters | One provider-boundary adapter only where contracts actually match. |
| Mixed domain/generic assertion catalogs | Typed specs and a small registry only when ownership becomes simpler. |

Keep the consequence threshold, S0-S3 independent of urgency/impact, useful DTOs,
protocols, facades, boundary catches and cohesive long routines. Every selected
file is inspected, partial or unreviewed explicitly. Remediation ordering follows
actual dependencies, not a copied refactoring sequence or fixed defect count.

## Intentional generalizations and limits

The generic project mapping resolves actual identities, time, permissions,
configuration, diagnostics, domain decisions, readiness, provisioning and recovery.
Examples do not supply a vendor schema, real ticket policy, journal width, complete
portfolio or expert acceptance certificate. Exact source-specific reconstruction
is a non-goal; missing original evidence cannot be filled by a model or similarity.

Behavioral red/green fixture checks and package integrity are local observations,
not agent adherence, host routing, scientific validity or recovered upstream fidelity.
Keep all candidate IDs and unresolved source/authority disputes through explicitly
selected Debate. Consensus is not evidence and missing stages are incomplete.
