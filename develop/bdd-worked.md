# Worked BDD: identity before writes

These self-contained fictional implementations exercise two submission contracts.
Select the example relevant to the target. Both use
Python 3.11+ standard-library `unittest`, a real public submission boundary and a
mock of the external write contract, not internal helper-call assertions.

## Fictional inventory-event submission

**Outcome:** an intake submission with no canonical event ID returns
`missing_canonical_event_id` and never calls the writer. The application supplies
`canonical_event_id`; a display label cannot supply or replace it. Missing,
null, non-string and blank IDs are invalid. Valid IDs are opaque, case-sensitive
and passed unchanged; this increment does not check catalog membership. Preserve
all caller-supplied fields, successful receipts and the existing writer-exception
behavior. No evidence timestamps or domain judgments are derived here.

| Given | When | Then |
|---|---|---|
| A labeled event missing its canonical ID | Submit | Precise invalid result; no external write |
| A null, blank or non-string canonical ID | Submit | Same rejection, independent of display label |
| An event carrying an authoritative ID | Submit | One write of the unchanged record; return its receipt |
| The writer fails for a valid event | Submit | Existing exception propagates; no automatic retry |

### 1. Unchanged baseline

`intake.py` already supports valid submissions. Do not edit this file until the
new test below has demonstrated the intended failure.

```python file=intake.py stage=baseline
def submit_event(record, write_event):
    receipt_id = write_event(record)
    return {"status": "submitted", "receipt_id": receipt_id}
```

### 2. Tests before production

Save `test_intake.py` alongside the baseline. The valid-submission and exception
tests characterize existing behavior; the rejection test is new. Its first
assertion checks the no-write contract, so a misleading error result after a
write cannot pass.

```python file=test_intake.py stage=test
import unittest
from unittest.mock import Mock

from intake import submit_event


class IntakeTests(unittest.TestCase):
    def test_missing_identity_never_writes(self):
        records = [
            {"display_name": "Equipment inspection"},
            {"canonical_event_id": None},
            {"canonical_event_id": ""},
            {"canonical_event_id": " \t"},
            {"canonical_event_id": 42},
        ]
        for record in records:
            writer = Mock(return_value="receipt-8")
            result = submit_event(record, writer)
            writer.assert_not_called()
            self.assertEqual(result, {
                "status": "invalid", "error": "missing_canonical_event_id"
            })

    def test_valid_submission_preserves_the_boundary(self):
        record = {
            "canonical_event_id": "evt-27", "display_name": "Equipment inspection",
            "occurred_at": "2026-03-11T09:30:00Z"
        }
        original = dict(record)
        writer = Mock(return_value="receipt-8")
        result = submit_event(record, writer)
        writer.assert_called_once_with(original)
        self.assertEqual(record, original)
        self.assertEqual(result, {"status": "submitted", "receipt_id": "receipt-8"})

    def test_writer_failure_is_not_retried(self):
        record = {"canonical_event_id": "evt-27"}
        writer = Mock(side_effect=RuntimeError("write rejected"))
        with self.assertRaisesRegex(RuntimeError, "write rejected"):
            submit_event(record, writer)
        writer.assert_called_once_with(record)
```

Run from that isolated directory, using its authorized Python interpreter:

```sh
python -m unittest -v test_intake
```

**Intended red:** 3 tests, 1 failure, 0 errors. The failure is
`test_missing_identity_never_writes`: `Expected 'mock' to not have been called.
Called 1 times.` The other two tests pass. A missing `intake` import, unavailable
interpreter or test discovery of zero tests would not count as red.

### 3. Minimal complete production change

Only after that red result replace `intake.py` with:

```python file=intake.py stage=green
def submit_event(record, write_event):
    canonical_id = record.get("canonical_event_id")
    if not isinstance(canonical_id, str) or not canonical_id.strip():
        return {"status": "invalid", "error": "missing_canonical_event_id"}
    receipt_id = write_event(record)
    return {"status": "submitted", "receipt_id": receipt_id}
```

Rerun the same command: **green**, 3 tests, 0 failures, 0 errors. All invalid
representations now execute, and the valid/exception characterization tests stay
green. Update the target API's identity-error documentation in a real project.

## Transfer: warehouse shipment release

This separate project owns an opaque `order_id`, not a domain-event identity.
An order label is not a booking key. The increment rejects a missing/null/blank/
non-string order ID without calling the carrier's booking boundary. Existing valid
booking confirmations and exceptions must remain unchanged. This is a successful
implementation exercise, not only a review of scenario wording.

Given an order without its canonical ID, when released, then return
`missing_order_id` with no carrier booking. Given an identified order, when
released, then book its unchanged payload once and return the carrier confirmation.
Given a carrier rejection, then propagate it without retrying.

### 1. Baseline

```python file=dispatch.py stage=baseline
def release_order(order, book_shipment):
    booking_id = book_shipment(order)
    return {"status": "released", "booking_id": booking_id}
```

### 2. Tests before production

```python file=test_dispatch.py stage=test
import unittest
from unittest.mock import Mock

from dispatch import release_order


class DispatchTests(unittest.TestCase):
    def test_missing_order_identity_never_books(self):
        orders = [
            {"label": "Blue crates"}, {"order_id": None}, {"order_id": ""},
            {"order_id": " \n"}, {"order_id": 17}
        ]
        for order in orders:
            carrier = Mock(return_value="booking-12")
            result = release_order(order, carrier)
            carrier.assert_not_called()
            self.assertEqual(result, {"status": "invalid", "error": "missing_order_id"})

    def test_valid_order_preserves_booking(self):
        order = {"order_id": "ord-56", "label": "Blue crates", "packages": 2}
        original = dict(order)
        carrier = Mock(return_value="booking-12")
        result = release_order(order, carrier)
        carrier.assert_called_once_with(original)
        self.assertEqual(order, original)
        self.assertEqual(result, {"status": "released", "booking_id": "booking-12"})

    def test_carrier_error_is_not_retried(self):
        order = {"order_id": "ord-56"}
        carrier = Mock(side_effect=RuntimeError("carrier rejected"))
        with self.assertRaisesRegex(RuntimeError, "carrier rejected"):
            release_order(order, carrier)
        carrier.assert_called_once_with(order)
```

`python -m unittest -v test_dispatch` against the baseline gives **red**:
3 tests, 1 failure (`test_missing_order_identity_never_books` at
`carrier.assert_not_called()`), 0 errors. The existing valid/error cases pass.

### 3. Production after red

```python file=dispatch.py stage=green
def release_order(order, book_shipment):
    canonical_id = order.get("order_id")
    if not isinstance(canonical_id, str) or not canonical_id.strip():
        return {"status": "invalid", "error": "missing_order_id"}
    booking_id = book_shipment(order)
    return {"status": "released", "booking_id": booking_id}
```

Rerun the identical command: **green**, 3 tests, 0 failures, 0 errors. Document the
new `missing_order_id` outcome at the warehouse submission API, not a domain
schema. No dependency, registry or intermediate abstraction is needed.

## Evidence and limits

The repository's focused test replays each baseline/test pair in a temporary
workspace, requires this assertion failure with no errors, then installs the
green implementation and reruns identical tests. These deterministic results
validate the examples, not model adherence, a live writer, access control,
catalog validity, transaction atomicity or domain safety. Static/governance
checks remain separate. If tests already pass in a real project, investigate and
retain them rather than copying an intentionally defective baseline into it.
