# Fictional prompt and backlog verification

Raw cases contain independently fictional document-processing, equipment and other
held-out examples. Evaluator-only expected observations stay separate from actor
context. The baseline is a constructed, hash-bound instruction snapshot.

## Observable contracts

The prompt tests execute strict wire/final shape rejection, application-owned
canonical identity, distinct issuance/receipt/processing meanings, missing-metadata
failure, logical version/hash, uncertainty and exact-run/step accepted-only replay.
Held-out document and freight adapters demonstrate actual timestamp conflation and
failed-event replay consequences. Fixture quote acceptance is explicit, not a
universal matching policy or proof that interpretation is correct.

Backlog tests execute normalization, partial increments, complete/incomplete page
chains, role/priority separation, existing-owner reuse, approval versus implementation,
conflicts, overlap, unknown versus a bounded gap and input immutability. There is
no real work portfolio, live tracker read, model call or new implementation owner.

traceability.json names the exact current tests and resources. Frozen raw inputs, criteria and artifact hashes identify the exact checked context.

```sh
.venv/bin/python -m unittest discover -s tests -p test_prompt_backlog_methods.py -v
```

Current observations are recorded separately from unperformed generation/host/model
quality. Example execution and static instruction assertions do not establish that
an assistant applies every instruction in an unrelated project. Any observed trial
requires the existing approval protocol and actual evidence, not simulated success.
