# Repository instructions

Follow [contributor guidance](CONTRIBUTING.md) and the
[repository profile](resources/profiles/skills.md). Runtime skill rules belong to
the owning method and [shared policy](resources/policy.md), not private originals.

- Never force-add, unignore, rename, copy, summarize, or embed ignored/private work
  to repair links or obtain green checks. Use approved canonical public resources
  or independently fictional examples. Report unavailable evidence instead.
- Do not read rejected link targets. Review proposed public content and provenance;
  tracked files, allowed filenames, and passing tests are not disclosure clearance.
- Do not edit generated resource views, frozen historical inputs, old archives, or
  qualification records to manufacture passing checks. Preserve user modifications.
- Source links must reach tracked, nonignored ordinary files. Portable exports use
  explicitly relocated package links; generated existence does not validate source.
- Run deterministic checks and use proportionate manual host testing. Do not add
  automated model evaluations, formal trial plans, or mandatory per-change host runs.
- Do not stage, commit, branch, install globally, or publish without the requested
  authority. Tests may stage synthetic files in disposable repositories; never
  stage this checkout merely to make source checks pass.
