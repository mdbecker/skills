# Saved-evidence report assembly and maintenance

`create` assembles an initial report through an existing mapped build graph from
approved saved inputs. `update` changes an existing report through that graph.
Neither gathers evidence, runs notebooks, fills model gaps or creates a pipeline.

1. Define scope/acceptance and classify presentation, explanation or evidence
   correction. Locate authoritative editable/generated inputs, build dependencies
   and source conflicts. Missing critical evidence/profile/access blocks work.
2. Capture versions/hashes and protected claims/values, cohorts/fingerprints,
   denominators, selection methods, comparisons, uncertainty, caveats and links.
   Creation uses saved evidence as baseline. Record restricted inputs/permitted
   aggregates/suppression and preserve unrelated work.
3. Edit authoritative templates/helpers/diagrams, not generated HTML. Preserve
   markers, allowlists, provenance and disclosure checks. Verify explanations
   against schemas/derivation code. Editorial work cannot change definitions,
   computed logic or uncertainty. Scientific corrections require explicit request
   and identified saved supporting evidence, not a new research run.
4. Rebuild with existing integrity/asset tools. Detect stale assets and inputs
   changing during generation. Preserve previous deliverable on failure; for first
   creation preserve inputs and do not advertise partial output as complete.
   Never silently omit sections or fabricate dependencies/results.
5. Compare protected evidence before/after, allowing only authorized supported
   corrections. Run focused/applicable broader checks and actually inspect charts,
   controls, links, narrow/print layouts and offline requests. Report pass/fail/
   blocked/not-run; no invented independent score or visual acceptance.

Cohort labels/counts do not prove matched samples, pooling legitimacy or improvement.
Keep source/cohort identity and denominator limits explicit. Reference output is
aggregate-only: no records, identifiers, sensitive quotes, credentials or private
artifacts. Existing pipeline processing does not authorize altered derivation.
No notebook/query/model execution, sending, publication or deployment follows.

Deliver source/output changes when authorized, protected-evidence comparison,
provenance and actual verification/limits. Schemas, metadata and visual helpers
are dependencies, not additional skill/extraction/deployment deliverables.
