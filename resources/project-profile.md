# Map the current project's contracts

Complete only the relevant fields from the user's actual target instructions and
evidence. This template supplies no business rules, vendor defaults or permission.
Missing essential target authority blocks the affected operation; do not
substitute unrelated sources. Inapplicable surfaces are not applicable.

| Area | Record authoritative source/version, owner, current contract and limits |
|---|---|
| Purpose and scope | User outcome, chosen method, included/excluded work and allowed effects. |
| Authority | Current instructions, decisions, superseded/conflicting sources and resolution owner. Newest text alone need not govern every field. |
| Surfaces | Editable inputs, generated outputs, consumers, actual pipeline and dependencies. |
| Compatibility | Public consumers, migration/retention obligations and established cleanroom exceptions. |
| Runtime | Existing suitable language/tools, prerequisites and separately permitted installation. |
| Checks | Canonical workflow, tested state, effects, exit/results and failed/blocked/not-run checks. Focused green does not replace required checks. |
| Identity | Canonical IDs, display-name selection, ambiguity, defaults and retry/idempotency identity. |
| Time | Source-issued, received, processed and occurrence meanings; application-owned enrichment and missing-metadata failure. |
| State and persistence | Recorder ownership, write-before-index advancement, recovery, exact replay selection and provision/migration authority. |
| Readiness and safety | Gates before external effects, configuration precedence, safe diagnostics and failure/no-write boundaries. |
| Evidence | Accepted output versus quote verification versus interpretation; source restrictions and uncertainty. |
| Work items | Actual metadata/editability, inheritance, retention, source ranks, delivery/support/validation roles and pagination completeness. |
| Reports and presentation | Approved saved inputs/build graph, definitions, disclosure thresholds, accessibility and protected outputs. Use the report profile for figure/scoring details. |
| Domain limits | Permitted judgments, prohibited conclusions, exact data/diagnostic allowlists and unresolved owner decisions. |
| Acceptance | Observable behavior, preserved contracts, manual observations and explicitly requested independent-review criteria. |
| Deployment evidence | Actual permitted deployed checks distinct from local tests; no inferred live success or new access permission. |

For every affected obligation record **contract -> authoritative source -> relevant
check -> observed result**. Preserve unrelated source/staging and distinguish
environmental failure from a demonstrated patch defect. Reuse existing tooling;
do not invent another runtime, registry, source acquisition or evaluation pipeline.

Independent scoring is never implicit. If requested, record the agreed rubric,
minimum, reviewer permission/budget, bounded revision loop and actual result in the
report profile. An unavailable required review remains blocked/not-run; no invented
score or automatic additional agent call. Scope and authority travel with handoffs.

Public reusable skills contain fictional examples and generic contracts only.
Project-specific mappings belong to the target project's permitted local context,
not the reusable package. Release/deployment authority, actual host invocation
and model quality are separate acceptance decisions.
